# Agent guide for Differ

Differ is a review-first desktop app built as a soft fork of [Zed](https://github.com/zed-industries/zed). It is a client of an unmodified [T3 Code](https://github.com/pingdotgg/t3code) server, which owns agents, pull request data, and worktrees. Differ owns the UI. The plan is in `differ-docs/PLAN.md`.

## The one rule: don't edit Zed

Pulling in new Zed and T3 Code releases has to stay a routine, scripted task. So:

- Differ's code lives only in Differ's own paths: `differ-crates/`, `differ-docs/`, `assets/themes/differ/`, `script/differ-*`, `.github/workflows/differ-*.yml`, and `THIRD_PARTY_NOTICES.md`.
- Never edit Zed's files (`crates/`, Zed's `script/`, `docs/`, `assets/`, and so on). The only touch points are the `differ-crates/*` line in the root `Cargo.toml`, `Cargo.lock` (regenerated by cargo), `README.md`, `CLAUDE.md`, and `AGENTS.md`.
- If something seems to need a change inside a Zed crate, stop and ask. First look for a public API, a setting, or a pattern to copy into a Differ crate. `crates/zed` has no library target, so copying its helpers is expected; cite the source file in a short comment.
- Syncing with upstream: follow `differ-docs/SYNC.md` and use `script/differ-sync-zed` and `script/differ-sync-t3`.

## Rust and GPUI

Follow these sections of Zed's `.rules`: "Rust coding guidelines", "Timers in tests", and "GPUI". They apply to Differ's crates unchanged.

Ignore the rest of `.rules`, which is for Zed's own repository: the README banner rule, "Pull request hygiene" (Zed's release-notes format), "Crash Investigation" (Zed's Sentry), and "Rules Hygiene".

## Building and testing

- Per crate: `cargo test -p <crate>`, `cargo clippy -p <crate> --all-targets`, and `cargo fmt -p <crate>`. Fix every warning.
- Linux builds need Zed's system packages (`script/linux`). GPUI tests use the test platform and don't need them.
- First builds of Zed crates take minutes; run them in the background.

## T3 Code servers

- `differ-crates/t3_client` talks to T3 over HTTP and WebSocket. `differ-crates/t3_client/T3_VERSION` pins the T3 version and orchestration protocol, which must match the server exactly.
- Live tests are ignored by default. When you run one against a real T3 server, mint a pairing token with only `--scope orchestration:read`, and revoke the session afterwards (`t3 auth session list`, `t3 auth session revoke`).
- Never request `access:write` or `relay:*` scopes, and never print tokens.

## Commits and pull requests

- Imperative, capitalized titles without trailing punctuation. Prefix with the crate name when one crate is the clear scope (`review: Add comment cards`).
- Keep each change focused, and say in the description how it was tested.
